---
name: Android emulator in this workspace
description: Recipe for standing up a working Android SDK + emulator locally despite no KVM and a small home-dir quota.
---

A full Android emulator CAN run in this workspace, contrary to earlier assumptions:

- **Disk:** the per-user quota (~5-6G) spans the overlay home AND /tmp together — a `mktemp` in /tmp fails with "Disk quota exceeded" when home is full, and a JVM under quota pressure dies with SIGBUS in `PerfLongVariant::sample` (hsperfdata mmap) unless `_JAVA_OPTIONS=-XX:-UsePerfData` is set for every java invocation (sdkmanager/avdmanager/gradle). **The workspace (`~/workspace`) is a separate device (/dev/vdf, 254G, no tight quota) since 2026-09 — relocate `GRADLE_USER_HOME`, `ANDROID_AVD_HOME`, disposable Postgres data, and logs under it** instead of trimming to fit the overlay quota. The SDK + system image (~4.5G) still fits in overlay home IF sdkmanager's `.temp` staging is deleted and the system image is stream-extracted with `curl ... | bsdtar -xf -` (`nix profile add nixpkgs#libarchive`; get the zip name from `https://dl.google.com/android/repository/sys-img/google_apis/sys-img2-1.xml`); skip platform-tools — symlink the nix adb into `platform-tools/`, which the emulator requires to validate the SDK root. Also: the adb server dies between separate shell invocations — start it and run all adb commands in ONE shell session; a hand-crafted AVD config.ini must include `abi.type=x86_64` / `hw.cpu.arch=x86_64` or the emulator FATALs assuming arm.
- **GUI libs:** the emulator binary needs `libX11.so.6`, absent from the container; find it in the nix store (`ls -d /nix/store/*libX11-*/lib`) and export via `LD_LIBRARY_PATH`.
- **No KVM:** pass `-no-accel` (x86_64 works under TCG despite the scary "requires hardware acceleration" check that only fires *without* the flag). Cold boot takes ~7 minutes; `am start -W` can report `Status: timeout` on a healthy app. Right after cold boot, package scanning lags — a launch immediately after install can fail with "Activity class does not exist"; on a busy post-boot TCG system this lag exceeded 60s, so retry the launch itself on that exact error (~90s budget) rather than probing `pm dump` (per-package dumps do not reliably list components) or blind-sleeping a few seconds.
- **Toolchain:** download cmdline-tools from dl.google.com and the pinned Gradle from services.gradle.org; system java 17 works. Network access to dl.google.com / services.gradle.org / Maven repos is available.
- **Lifecycle:** workspace restarts kill the emulator and background shells, but everything on the workspace volume persists; relaunch the same AVD. nohup/disown'd children of a background ShellExec task do NOT survive the task ending, so a "boot once, hold, probe from other shells" pattern requires the holding task to stay alive (e.g. `while true; sleep 3600`) — and side-channel `adb` from another shell while a run's boot loop is polling can disrupt that run (adb server restart); poll log files instead.
- **No cellular modem here (2026-09):** the emulated modem never registers in this container — netsimd initializes WiFi only, RILJ never connects, SIM never loads (subId -1, OUT_OF_SERVICE), `phone`/`isms` binder services never appear, and every `SmsManager` op throws `UnsupportedOperationException: Sms is not supported` (thrown by `getISmsServiceOrThrow` when the `isms` service is null). Features like `android.hardware.telephony.messaging` ARE declared, so feature checks don't predict it. Outbound-SMS flows can therefore only be verified up to the point of the radio send locally; the SENT transition needs CI (KVM-accelerated canonical AVD) or hardware.
- **Networking into the device:** the qemu `10.0.2.2` host alias does NOT reach servers on this container's loopback ("Failed to connect"). Use `adb reverse tcp:<port> tcp:<port>` and have the device talk to `http://127.0.0.1:<port>` — works for emulator and USB devices alike.
- **Snapshots:** restoring a saved snapshot after `-no-accel` TCG boots produced a dying system_server (DeadSystemException, `adb install` broken pipe); run with `-no-snapshot` and wipe `userdata*.img`/`snapshots` between verification runs. `sys.boot_completed=1` is not enough — poll `adb shell pm path android` before installing and retry `adb install`.

**Why:** standing this up once enabled real end-to-end APK/emulator verification locally when GitHub CI was unreachable; future Android verification tasks can reuse the recipe — but must not burn cycles trying to make outbound SMS work locally.

**How to apply:** Follow this recipe instead of concluding emulator verification is impossible; only *physical* Pixel runs still need the hardware workstation. For SMS send/receipt verification, prove everything except the radio-accept leg locally and let the CI emulator job own the SENT assertion.
