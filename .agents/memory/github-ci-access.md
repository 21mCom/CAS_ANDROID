- GitHub PUSH PROTECTION (GH013) scans EVERY commit in a push, so a secret-shaped literal anywhere in the unpushed HISTORY blocks the whole push — fixing only the tip tree never clears it. Never write the contiguous literal into any file, including memory/evidence — that re-creates the finding. Bypass no longer needs a browser: the PAT carries "Secret scanning push protection bypass requests", so `POST /repos/21mCom/CAS_ANDROID/secret-scanning/push-protection-bypasses` with `{"reason":"used_in_tests","placeholder_id":"<id from the unblock-secret URL the rejected push prints>"}` grants a 24h bypass; then re-push immediately. The historic Stripe doc-example literal was pushed on 2026-09-27 after exactly such a bypass, so it now lives in GitHub main's history and future pushes of that history are unaffected.
- The PAT expires **2026-12-27 02:43:08 UTC** (rotated 2026-09-27 via the secrets flow; verified with a green workflow_dispatch + contents-API commit). Check without printing the token: `curl -s -o /dev/null -D - -H "Authorization: Bearer $GITHUB_PAT" https://api.github.com/repos/21mCom/CAS_ANDROID | grep -i github-authentication-token-expiration`. Push with an explicit credentialed URL and askpass disabled (`GIT_ASKPASS= GIT_TERMINAL_PROMPT=0`) so the token never prints; a Basic `http.extraHeader` works, a Bearer `http.extraHeader` does NOT — use Bearer only for the Actions REST API. Multiple sessions push from this workspace, so always `git fetch` and rebase onto FETCH_HEAD immediately before pushing and expect non-fast-forward rejections.
- REPO SECRET SCANNING is now ENABLED (2026-09-27): repo Settings → "Security and quality" → Advanced Security → "Secret Protection" → Enable (GitHub's current UI names the product "Secret Protection"; per GitHub docs, enabling it turns on secret scanning alerts, and push protection was already active). As of 2026-09-28 the fine-grained GITHUB_PAT carries Administration: Read and write and Secret scanning alerts: Read and write for CAS_ANDROID (user edited the existing token in place — same string, no secret update needed). Alert checks are one curl, no browser: `curl -s -H "Authorization: Bearer $GITHUB_PAT" https://api.github.com/repos/21mCom/CAS_ANDROID/secret-scanning/alerts`. The GitHub connector remains read-only and 403s on this endpoint — always use the PAT. Administration: write was granted but not yet exercised (e.g. PATCH /repos security_and_analysis toggles); verify before relying on it. The PAT also carries Secrets: Read and write (granted 2026-09-28), which unlocks the repo Actions-secrets API (`gh secret set` works with `GH_TOKEN=$GITHUB_PAT`, value piped via stdin).
- **Actions' GITHUB_TOKEN is platform-blocked from the secret-scanning alerts API** (403 "Resource not accessible by integration"; `security-events: read` does NOT cover it). CI jobs that poll alerts must use a repo Actions secret: `CAS_ALERT_SCAN_PAT`, holding a DEDICATED fine-grained PAT with only "Secret scanning alerts: Read" — never the push-capable workspace PAT, because push-triggered workflows run branch code and would hand those write powers to any collaborator's branch. `.github/workflows/secret-scanning-watchdog.yml` (push + daily cron) fails red naming the open-alert count + dashboard URL when any alert is open, and also fails red on any non-200 so an unknown state never looks green; the dedicated token's own expiry lapse is what turns it red, and its rotation is documented in the workflow header (independent of workspace-PAT rotation).

**Why:** Two OAuth setup attempts and repeated askpass failures (timeouts, then invalid tokens) failed before the PAT path worked, and a concurrent session caused a rejected push mid-task — this cost several failed CI runs to learn.

**How to apply:** For any "confirm CI on GitHub" or push-to-GitHub task in this project, go straight to GITHUB_PAT via the credentialed URL, poll `/actions/runs` for the workflow, and rebase-then-push. If the PAT lapses, request a fresh one via the secrets flow — the alternatives are dead ends (`replit-git-askpass` mints an invalid token, and the connector's app token is read-only, so its writes 403). The repo runs `pat-expiry-watchdog.yml` (push + daily cron) which turns red 60 days before the PAT expiry recorded in it; when rotating, update `PAT_EXPIRES_AT` in both the GitHub and workspace copies of that file. Never mark a "real CI" task complete on local simulation alone — a completion review rejected a verbatim local replay of a workflow step; local replay is pre-validation only.

**Superset claims need full `-`-line review:** the 83366d2 sync clobbered the remote lineage's `arm64-v8a` arch fix for the macOS emulator job because the "remote has nothing unique" verdict rested on a `head -30`-truncated sample of removed lines; the macOS SMS-flow job timed out on AVD creation (run 36322629091) until 8fe01c2 restored it. When declaring one lineage a superset of another, review EVERY removed line of the tip diff, not a sample.

**macOS emulator job retired:** the arm64-v8a restore (8fe01c2) could never have been enough — macOS runners lack nested virtualization, so the sms-receipt-flow job died with HVF HV_UNSUPPORTED on every macOS run. The job now runs on ubuntu-latest + KVM + x86_64 (see android-emulator-ci.md).

**Local pre-validation technique:** to sanity-check a workflow gate before burning a CI run, extract the step's `run:` body verbatim from the workflow YAML (awk between the step name and the next step, strip the 10-space indent, keep blank lines), build inputs with the real script block (for the kit packager: the staging block from `$stagingRoot = ...` to EOF via Invoke-Expression), and run the step as a ScriptBlock with the same env vars from the workspace root. The packaging script cannot run end-to-end locally — it shells out to powershell.exe. Its `'app\build'`-style backslash Join-Path segments only resolve on Windows; harmless today because no Gradle outputs are committed.
