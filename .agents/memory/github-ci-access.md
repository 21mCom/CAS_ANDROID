- GitHub PUSH PROTECTION (GH013) scans EVERY commit in a push, so a secret-shaped literal anywhere in the unpushed HISTORY blocks the whole push — fixing only the tip tree never clears it; the literal must be purged from history (or browser-unblocked). Never write the contiguous literal into any file, including memory/evidence — that re-creates the finding. The printed `unblock-secret/...` URL needs a logged-in browser (404s with a PAT).

**Why:** Two OAuth setup attempts and repeated askpass failures (timeouts, then invalid tokens) failed before the PAT path worked, and a concurrent session caused a rejected push mid-task — this cost several failed CI runs to learn.

**How to apply:** For any "confirm CI on GitHub" or push-to-GitHub task in this project, go straight to GITHUB_PAT via the credentialed URL, poll `/actions/runs` for the workflow, and rebase-then-push. If the PAT lapses, request a fresh one via the secrets flow — the alternatives are dead ends (`replit-git-askpass` mints an invalid token, and the connector's app token is read-only, so its writes 403). The repo runs `pat-expiry-watchdog.yml` (push + daily cron) which turns red 60 days before the PAT expiry recorded in it; when rotating, update `PAT_EXPIRES_AT` in both the GitHub and workspace copies of that file. Never mark a "real CI" task complete on local simulation alone — a completion review rejected a verbatim local replay of a workflow step; local replay is pre-validation only.
